One product loop, three clear roles.

Prism and Shale are the two core projects. They work with the tools developers already use and do not require a hosted control plane. Mason is the reference implementation that proves the two layers can work as one system.

Prism: before the edit. Deterministic change impact, missing implementations, untested surfaces, rename plans, affected tests, and ranked task context.
Shale: after the edit. Intent, touched files, observed checks, evidence integrity, and explicit gaps travel with the pull request.
Mason: the proving ground. A reference agent where accuracy-critical behavior is enforced by the harness and measured against published oracles.
No hosted dependency. The default path is local-first open source. No account, server URL, or token paste.

Why these names?

The product line is named for how each tool treats the raw material of software work. Provasign is the umbrella: prova (proof) + sign — agent work that can prove itself.

Shale is sedimentary rock: thin, readable layers compacted from what settled. Shale compacts a messy agent session into clean strata of evidence on the pull request.
Prism splits white light into a spectrum. Point a task at your codebase and Prism refracts it into exactly the bands an agent needs — code, callers, tests, coverage gaps — ranked and budgeted.
Mason is the builder's trade: courses laid level, checked against the line, on a foundation that holds. The agent does the work; the harness is the level and the plumb — accuracy comes from the structure, not the worker's mood.
